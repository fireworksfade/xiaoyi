# ESP32 I2C 传感器通信故障诊断

来源：Espressif ESP-IDF I2C 官方文档。
适用范围：ESP32 I2C Master、常见温湿度与环境传感器。

## 典型症状

日志可能包含 NACK、device not found、ESP_ERR_NOT_FOUND、ESP_ERR_TIMEOUT、bus busy、arbitration lost、invalid response、sensor read failed，或者采样值长时间不变。诊断应记录 I2C 端口、SDA/SCL GPIO、设备地址、地址位数、总线频率、超时时间、重试次数和失败阶段。

## NACK 与 Timeout 的区别

探测设备时收到 NACK，通常表示该地址没有设备响应，优先检查 7 位地址、供电、接线、设备是否处于复位或休眠状态。Timeout 表示事务未在给定时间内完成，更常见于 SDA/SCL 被拉低、上拉电阻不合适、总线繁忙、时钟拉伸过长或硬件异常。两者处理路径不同，不应统一标记为“传感器离线”。

## 确认步骤

第一步执行地址扫描并记录 ACK/NACK。第二步用逻辑分析仪或示波器查看 START、地址、ACK、数据和 STOP，确认 SDA/SCL 是否能回到高电平。第三步检查外部上拉电阻；内部上拉通常较弱，在高频或较长连线场景可能不足。第四步降低 SCL 频率并延长合理的传输超时，观察故障是否消失。第五步核对传感器数据手册中的启动延迟、测量等待时间、寄存器地址和 CRC。第六步在失败后检查总线是否仍忙，必要时按设备手册执行总线恢复或重新初始化外设。

## 常见根因

使用了包含读写位的 8 位地址，而驱动需要原始 7 位地址；SDA/SCL 接反或 GPIO 配置错误；传感器电压与 ESP32 电平不兼容；缺少公共地；上拉阻值不合适；线缆过长导致边沿过慢；多个任务未经协调访问同一总线；设备测量尚未完成就读取；传感器被意外复位或进入低功耗模式。

## 数据异常但通信成功

ACK 成功并不保证数值可信。应继续检查量程、单位、字节序、符号位、CRC、采样周期和校准系数。连续相同值可能是读取了旧寄存器、转换未完成或缓存未更新。越界、突变和漂移需要与参考传感器、环境条件以及供电变化交叉验证。

## 处理建议

修正地址和引脚，配置可靠的外部上拉，选择与总线电容匹配的频率。对瞬时 NACK 使用有限次数重试，但持续 NACK 必须上报具体地址和阶段。Timeout 后不要立即无限重试，应先恢复总线或重新初始化。修复后同时验证地址探测、连续采样、CRC、异常恢复和多小时稳定性。
